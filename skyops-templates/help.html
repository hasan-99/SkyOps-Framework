Skills

Road — Core Flow

The seven steps every project walks through.

/sky-newSet up a new project from scratch — deep questioning, parallel research, REQUIREMENTS.md, ROADMAP.md, approval gate. Use when starting any new client project.
/sky-planPlan the current phase — spawns planner, validates with plan-checker in a revision loop (max 2), optionally runs discuss/research first. Use when ready to plan a phase.
/sky-buildExecute the current phase — spawns builder subagents per task with wave-based parallelization. Fresh context per task.
/sky-verifyGoal-backward verification — checks if the phase ACTUALLY works, not just if tasks completed. Spawns verifier agent.
/sky-polishDesign and UX pass — anti-AI-slop, genuine craft, responsive, accessible. Run after all phases are verified.
/sky-shipDeploy to production — quality gates, commit, push, deploy, verify. Use when ready to go live.
/sky-handoffClient delivery — credentials, handover doc, final update. Use after shipping.

Phase Depth — Optional

Used before / around /sky-plan when a phase needs deeper context.

/sky-scopeUnified intake. No args: non-technical kickoff discovery before /sky-new. With N: archetype-aware adversarial grill before /sky-plan, gated on Definition-of-Done. Use for complex phases with regulatory, compliance, or architectural stakes. Creates .planning/phase-{N}-context.md that the planner honors as locked input.
/sky-researchDeep-research a niche domain or library BEFORE planning a specific phase. Spawns the researcher agent with Context7/WebFetch access. Writes to .planning/phase-{N}-research.md.
/sky-mapMap an existing codebase to infer architecture, stack, conventions, and what's already built. For brownfield projects — run BEFORE /sky-new so Validated requirements get inferred from existing code.
/sky-milestoneClose out a completed milestone and prep the next one. Archives the current milestone's artifacts, updates REQUIREMENTS.md to mark v1 requirements Complete, and creates the next milestone roadmap.

Quality

Fix, diagnose, audit, optimize, polish, test.

/sky-doctorFramework health check — install, state, contracts, memory, hooks, and scoped synchronization queue. Use when SkyOps itself feels broken or Codex/Claude is not picking it up.
/sky-fixRepair broken existing behavior — build a feedback loop, find root cause, patch minimally, verify, write a fix report. Trigger on 'fix this', 'bug', 'broken', 'failing test', 'regression'.
/sky-reviewRead-only production audit with scored diagnostics. Runs real commands, scores findings by severity, then routes repairs to /sky-fix, /sky-polish, or /sky-optimize.
/sky-optimizeDeep improvement discovery — reads .planning/ AND codebase to find performance, design, UI, backend, alignment, and architecture opportunities. Writes OPTIMIZE.md/RFCs; specific repairs route through /sky-fix.
/sky-testGenerate or run tests for client projects. Trigger on 'write tests', 'add tests', 'test this', 'test coverage'.

Quick Paths

Lightweight alternatives when the full road is overkill.

/sky-featureAuto-scoped new-feature build. Inline for trivia (copy, config), fresh builder spawn for 1-5 file features. Broken existing behavior routes to /sky-fix. Flags: --force-spawn, --force-inline.
/sky-polishVisual quality pass, scope-adaptive — component, route, full app, redesign, critique, quick. It fixes style/layout/accessibility only; functional bugs route to /sky-fix.
/sky-polish --vibeFast aesthetic-token pivot (~3 min) — swap color, type, depth, and motion, keep layout untouched. Structural redesign routes to /sky-polish --redesign.

Verification Scoring

Every phase is scored on 4 dimensions. Any score below 3 = automatic FAIL.

Correctness

Does it work as expected?

Completeness

Are all requirements met?

Wiring

Is everything connected end-to-end?

Quality

Code quality, security, a11y?

Rules

  • 1 Feature branches and configured protections — local role labels grant no privileged override
  • 2 Read before write — understand files before editing
  • 3 MVP first — build what's asked, nothing extra
  • 4 /sky-report preserves development context — not attendance or worker-performance data
  • 5 Secrets through secure scoped configuration — never put keys in chat, source or logs
  • 6 Escalate a genuine blocker to an authorized project maintainer
